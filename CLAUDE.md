# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CozyTime is a private macOS SwiftUI app (one trusted user, ad-hoc-signed distribution). It combines focus timer, tasks, countdowns, habits, and a mascot/reward progression system. **Deployment target is macOS 15.0, Swift 6.** The single deploy machine is an M2 MacBook Air on macOS 15.1 Sequoia, so the codebase is free to adopt macOS 15-only SwiftUI / SwiftData / UserNotifications APIs.

## Two Build Paths (important)

The repo intentionally has **two parallel build systems** for the same app, and several files only belong to one of them. Know which path you are touching before editing:

- **SwiftPM (`Package.swift`)** — fast domain-only path. The app target builds, but the `AppDataStore` here uses **JSON persistence** (`~/Library/Application Support/CozyTime/CozyTimeData.json`). This path exists so `swift test` can exercise `CozyCore` without Xcode. It is **dev-only**: `scripts/package_app.sh` refuses to build unless `COZYTIME_ALLOW_SWIFTPM_PACKAGE=1`.
- **Xcode (`CozyTime.xcodeproj`, generated by XcodeGen from `project.yml`)** — the real release path. Uses **SwiftData** for persistence, plus asset catalogs, entitlements, Info.plist, and UI test target. This is what ships.

The Xcode target source list (see `project.yml`) **excludes** `Sources/CozyTime/AppDataStore.swift` and substitutes `XcodeSupport/CozyTime/SwiftDataAppDataStore.swift`. Both files expose the same `AppDataStore` API — they are alternate backends of one ObservableObject, not two unrelated classes. When you change one, you almost always need to change the other to keep the API in lock-step. The SwiftData store also runs a one-time JSON→SwiftData migration on first launch.

`CozyTime.xcodeproj` is **generated**. Do not hand-edit the pbxproj. Edit `project.yml` and re-run `scripts/generate_xcode_project.sh`.

## Common commands

```bash
# Domain-level tests (no Xcode required, fast)
swift test

# Regenerate Xcode project after editing project.yml
# Also regenerates Assets.xcassets via scripts/generate_xcode_assets.swift
scripts/generate_xcode_project.sh

# Xcode unit tests
xcodebuild -project CozyTime.xcodeproj -scheme CozyTime \
  -destination 'platform=macOS,arch=arm64' \
  -only-testing:CozyTimeTests test

# Full release test plan (unit + UI tests) — the formal release gate
scripts/run_xcode_release_gate.sh

# Archive and produce the private ad-hoc-signed ZIP at .build/xcode/CozyTime-unsigned-xcode.zip
# (runs the release gate first unless COZYTIME_SKIP_RELEASE_GATE=1)
scripts/package_xcode_unsigned.sh

# Run a single SwiftPM test
swift test --filter CozyCoreTests.TimerEngineTests/testSomething
```

UI tests (`CozyTimeUITests`) are part of the formal release gate and passed on this machine through `scripts/run_xcode_release_gate.sh`. If a future Xcode session times out while enabling UI automation, treat that as a local Xcode automation/session issue to resolve before release, not as permission to waive the gate. The app supports a `-ui-testing` launch argument that resets defaults and seeds state (see `CozyTimeApp.swift`).

## Architecture

Three Swift modules:

- **`CozyCore`** (`Sources/CozyCore/`) — pure, dependency-free domain layer. All models (`TaskItem`, `CountdownEvent`, `FocusSession`, `Habit`, `RewardItem`, `CozyDatabase`), the timer state machine (`TimerEngine.swift`, `FocusTimerSnapshot`), reward/XP math (`Progression.swift`, `HabitMath.swift`), filtering (`TaskFilters.swift`), and notification scheduling drafts (`NotificationDraft.swift`) live here. No SwiftUI, no AppKit, no platform I/O. This is the only module covered by `swift test`.
- **`CozyTime`** (`Sources/CozyTime/`) — the SwiftUI app shell. Persistence (`AppDataStore` — see two-build-paths note above), the `FocusTimerStore` ObservableObject wrapping `TimerEngine`, `NotificationService` (UserNotifications), `StatusBarController` (AppKit NSStatusItem in the menu bar), views (`RootView`, `TodayView`, `FocusViews`, `TaskViews`, `CountdownViews`, `HabitStatsViews`), `DesignSystem.swift` (themes, mascot styles, timer skins), and `Commands.swift` (menu commands).
- **`CozyCoreSelfTest`** (`Sources/CozyCoreSelfTest/main.swift`) — tiny executable smoke check against the domain layer.

Data flow: `AppDataStore` holds the canonical `CozyDatabase` and is the single source of truth for persisted records. `FocusTimerStore` is a separate store for the live timer snapshot (kept in `UserDefaults`, not in the database). Both are injected as `@EnvironmentObject` from `CozyTimeApp`. `StatusBarController` observes `FocusTimerStore` via Combine to update the menu bar.

Test layout mirrors the split:
- `Tests/CozyCoreTests/` — pure domain tests, run by both `swift test` and the Xcode `CozyTimeTests` bundle.
- `XcodeTests/CozyTimeTests/` — Xcode-only tests (e.g. `SwiftDataMigrationTests`, `FocusTimerStoreTests`) that need the app target.
- `XcodeTests/CozyTimeUITests/` — XCUITest.

## Design system

`docs/DESIGN_SYSTEM.md` is authoritative for visual decisions. Key rules to honor when editing UI:

- Don't hard-code light-mode text colors into cards — use semantic primary/secondary styles so dark mode stays readable.
- The mascot is **Mochi** (Maltese-style); avoid sad/punitive states or streak-shaming copy. Missed work is "restart gently," never "you failed."
- Progression is additive only — never subtract XP or remove coins.
- Honor Reduce Motion: replace movement with fades/static color changes; keep idle animation rare.

## Bundle / paths

- Bundle ID: `dev.local.cozytime`.
- **App is not sandboxed.** `Packaging/CozyTime.entitlements` is intentionally empty (`<dict/>`) — no `app-sandbox` key — and `codesign -d --entitlements -` on the built app returns no entitlements. Both the Xcode/SwiftData build and the SwiftPM/JSON dev build read and write under `~/Library/Application Support/CozyTime/`.
- Legacy JSON migration source (read once on first launch of the SwiftData build, then ignored): `~/Library/Application Support/CozyTime/CozyTimeData.json`. This is also the file the SwiftPM dev build writes, so switching between dev and Xcode builds is seamless on first run.
- A `~/Library/Containers/dev.local.cozytime/` directory may exist on this machine as leftover prototype data from an earlier sandboxed build. The current target does not read or write it; treat it as cruft you can delete during cleanup (see `docs/INSTALL.md`).
